You own `apps/web` except the scene graph, which belongs to `threed-viz-engineer`.

Read `CLAUDE.md` first.

## Types are generated, never hand-written

Export `PositionEstimate.model_json_schema()` from pydantic, generate TypeScript from it,
commit the output, and **fail the build when the generated file differs from the committed
one**. A hand-written interface drifts the moment a field is added, and the drift shows up
as a silently missing ellipse rather than a type error.

Codegen covers shape only. It cannot express that `zone_only` carries no coordinates —
cover semantics with golden fixtures generated by Python and consumed by both test suites,
so the renderer can never work against a payload the engine does not produce.

## One conversion, declared once

The site frame is metres, right-handed, **+z up**. Three.js is **y-up**. Map it in exactly
one function with tests on both sides. Every project that leaves this implicit ends up with
the transform re-derived in four components and two of them wrong.

The ellipse angle has a modulo-π ambiguity — an ellipse axis is a line, not a vector — and
the handedness flip means the rotation must be negated. Pin it with a test using an
**asymmetric** covariance; a symmetric one passes either sign and hides the bug.

## State

The entity buffer is typed arrays outside React entirely. WebSocket messages write straight
into it with **zero `setState`**. The only React-visible change is a membership version,
coalesced, via `useSyncExternalStore` with a referentially stable snapshot — React 19 will
loop on a fresh array.

`zustand` holds UI state only: focused floor, selection, filters. Never entity positions.

## Privacy reaches the DOM

The entity list and hover labels are where a hashed identifier becomes a de-facto name on
screen, and every selection is a **location read** that must be audited (R17). Route
selection through an endpoint that logs, not a client-side lookup. Know whether the site is
in asset mode or people mode and render accordingly (R15).

## Verify in a real browser

`agent-browser` with deterministic accessibility refs, not CSS selectors. Assert the
detail panel's `zone_id` matches the selected volume — the label and the geometry come from
one estimate and must be provably incapable of disagreeing.
